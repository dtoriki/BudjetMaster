# Dtoriki.BudjetMaster

Приложение для хранения, обработки и отображения статистических данных по доходам и расходам.
Позволяет вести бюджет по периодам, отслеживать отклонения от медианного уровня трат и управлять несколькими счетами.

**Целевая платформа:** .NET 10 · MAUI · PostgreSQL

## Цель проекта

- Хранить транзакции (доходы и расходы) из нескольких источников: ручной ввод, импорт через API, загрузка из файла.
- Вести расчётные периоды с установленными бюджетными лимитами.
- Считать ежедневный лимит трат с учётом остатков предыдущих дней.
- Показывать ежедневное отклонение фактических трат от медианного уровня.
- Визуально разбивать траты на настраиваемые зоны (число зон, названия и пороги — произвольные).
- Поддерживать несколько счетов; в будущем — сберегательные и брокерские счета.

## Архитектура

Проект построен по принципам **Clean Architecture**. Подробные диаграммы — в [`docs/architecture.md`](./docs/architecture.md).

```
Dtoriki.BudjetMaster/
├── src/
│   ├── Domain/          — сущности, value objects, интерфейсы репозиториев
│   ├── Application/     — use-cases, DTO, интерфейсы сервисов
│   ├── Infrastructure/  — EF Core, PostgreSQL, импортеры (API, файл)
│   └── Maui/            — UI-слой (MAUI, MVVM)
└── tests/
    └── ...
```

Ключевые архитектурные решения:

- Источники транзакций (ручной ввод / API / файл) реализованы через интерфейс `ITransactionImporter` — добавление нового канала не затрагивает доменный слой.
- Алгоритм расчёта ежедневного лимита абстрагирован через `ILimitCalculator` — можно подключить любую стратегию без изменения остального кода.
- Типы счетов (`Checking`, `Savings`, `Broker`) разделены на уровне доменной модели, что позволяет добавить сберегательные и брокерские счета без рефакторинга существующих сущностей.

## Доменная модель

Полная диаграмма классов — в [`docs/domain-model.md`](./docs/domain-model.md).

Ключевые сущности:

- `Account` — счёт (расчётный / сберегательный / брокерский).
- `Transaction` — транзакция (доход или расход) с указанием источника.
- `BudgetPeriod` — расчётный период с общим бюджетом.
- `DailyBudget` — ежедневный лимит и фактические траты за день.
- `SpendingZoneDefinition` — произвольное число зон с названием, цветом и порогом.
- `ILimitCalculator` — интерфейс алгоритма расчёта лимита.

## План реализации

Подробный план с диаграммами зависимостей и задачами по фазам — в [`docs/roadmap.md`](./docs/roadmap.md).

Кратко:

1. **Фаза 1 — Домен** — сущности, интерфейсы, перечисления.
2. **Фаза 2 — Инфраструктура** — EF Core, PostgreSQL, репозитории, миграции.

6. **Фаза 6 — MAUI UI** — экраны, MVVM, навигация.
7. **Фаза 7 — Тесты** — пишутся параллельно с каждой фазой.
8. **Фаза 8 — Расширения** — сберегательные/брокерские счета, новые источники, экспорт.

## Запуск

> Инструкция будет дополнена по мере реализации.

Предварительные требования: .NET 10 SDK, PostgreSQL 16, Docker (опционально).

```bash
# Клонировать репозиторий
git clone https://github.com/dtoriki/BudjetMaster.git
cd BudjetMaster

# Применить миграции
dotnet ef database update --project src/Infrastructure

# Запустить MAUI-приложение
dotnet run --project src/Maui
```
